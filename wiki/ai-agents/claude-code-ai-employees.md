## Overview

AIMAX_PD 채널의 실전 팁 8편을 한데 묶었다. 관통하는 주장은 하나다: **클로드를 챗봇(질문→답변→새 대화 반복)으로 쓰지 말고, 반복 업무를 대신 처리하는 "직원"이자 비즈니스의 운영체제(OS)로 세팅하라.** 그 방법은 세 층으로 나뉜다. (1) 프롬프트를 정교하게 다뤄 결과 품질을 끌어올리는 **사용 기법**, (2) 워크플로우를 재사용 가능한 파일로 굳히는 **스킬·플러그인**, (3) 광고·고객센터·콘텐츠·웹디자인처럼 특정 직무를 통째로 맡기는 **'직원'화 사례**다.

에이전트 팀·오케스트레이션·슬래시 명령어 같은 팀 구성 개념은 이미 [클로드 에이전트 스택](claude-agent-stack.md)과 [Harness 100](harness-100.md)에서 다뤘으므로, 이 글은 그 위에 얹히는 **개인·소상공인 단위의 구체적 활용 팁**에 집중한다.

> 톤 주의: 원본 영상들은 "미쳤음", "비밀무기 31가지", "게임 끝" 같은 홍보성 프레이밍과 미검증 수치(비용 5% 절감, 판매가 $1,000~5,000 등)를 포함한다. 여기서는 실행 가능한 기법만 추리고 수치·과장은 근거로 삼지 않는다.

## 1. 클로드를 똑똑하게 쓰는 프롬프트 기법

"마케팅 전략 짜줘" 같은 단순 명령은 맥락이 0이라 AI가 스스로 가정을 세워 일반론을 낸다. 결과가 실망스러워 결국 사람이 다시 쓰는 악순환의 원인이다. 품질은 프롬프트 길이가 아니라 **AI가 확보한 맥락의 양·정확도**가 결정한다. 검증된 다섯 기법(2026-06-18):

1. **인터뷰 기법 ("나를 심문하라")** — 곧장 결과물을 시키지 말고 `"이 프로젝트를 이해하기 위해 필요한 질문을 하나씩 던져줘"`. 청중·예산·KPI·기대 보고서 형식을 10~15개 질문으로 뽑아내면 AI가 웬만한 팀원보다 깊은 이해도를 갖는다. 제안서·전략 문서 작성 전 필수.
2. **다각도 검토** — 본인 시점 하나로 제출하지 말고 3인칭 비판 검토를 시킨다. CFO 관점(ROI·비용 예측 허점), 클라이언트 관점(너무 일반적·안 맞음), 회의적 이사회 관점(전략 리스크·논리 허점). 관점당 30초, 전체 10분이면 훨씬 견고해진다. ([에이전트 스택](claude-agent-stack.md)의 병렬 다관점 토론을 1인 프롬프트로 축약한 형태.)
3. **단계별 문서 생성 (Chain of Documents)** — 15페이지 제안서를 한 번에 시키면 망한다(연구·구조·톤을 동시 처리 못 함). ① Brief(한 페이지 설계도) → ② Research → ③ Outline → ④ Final Draft로 쪼갠다. 구조적 결함을 초기 단계에서 2분 만에 고칠 수 있는 게 진짜 이점.
4. **프로젝트 구조 분해** — 전체 범위를 주고 독립 과업으로 분해 + **종속성 분석**을 시킨다("법무 검토 전엔 가격 페이지 공개 불가"). 첫날 할 일과 나중 일이 갈리고, 분해된 목록은 그대로 상태 보고서가 된다.
5. **지속적 맥락 (Projects 기능)** — 매 대화마다 역할·회사 배경·선호 문체를 반복 설명하면 주당 1시간+ 낭비. 클로드 프로젝트에 역할·제품 정보·템플릿·이해관계자 명단을 미리 로드해 두면, "보고서 써줘" 한 줄에 이미 내 톤·형식으로 답이 나온다.

이 다섯은 결합할수록 시너지가 난다: 인터뷰로 정보 확보 → 단계별 생성 → 다각도 검토 → 프로젝트로 반복 설명 제거.

## 2. 스킬·플러그인·비밀 기능

### 스킬 vs 플러그인

- **스킬(Skill)**: 특정 워크플로우를 수행하는 자동화 매크로. 이름·설명·구체 지침을 담은 텍스트 파일이다(예: `/job-post-builder`).
- **플러그인(Plugin)**: 개별 스킬들을 비즈니스 성격에 맞게 묶은 번들.

### 바로 이식할 만한 스킬 9종 (2026-05-14)

- 비개발자용: **Skill Creator**(반복 워크플로우를 스킬 파일로 제작), **Prompt Master**(생각을 구조화된 프롬프트로 변환), **Fact Checker**(외부 소스 대조 검증), **Humanizer**(AI 문체 제거 + 내 말투 학습).
- 개발·시스템용: **Playwright & Superpowers**(실제 사용자처럼 테스트 수행), **Septum Agents Pack**(기획·브랜드·디자인·마케팅·재무 등 전문가 에이전트 10명 투입 — [에이전트 팀](harness-100.md) 계열), **Review & Security Review**(로컬에서 버그·보안 즉시 검토), **Context & Compact**(컨텍스트 창 노이즈 관리로 기억력 유지).

### 자가 진화형 스킬 (learnings.md) — 진짜 핵심

여러 영상이 공통으로 강조하는 자산은 도구가 아니라 **누적된 피드백**이다. 스킬 파일 옆에 `learnings.md`를 두고 스킬 실행 전 반드시 읽게 설정한다. "헤드라인엔 숫자 포함", "수동태 금지", "이 단어 금지" 같은 교정을 쌓으면 단순 프롬프트가 아니라 **비즈니스의 '제도적 기억'**이 된다. 도구는 누구나 깔지만 이 누적 피드백은 복제 불가능한 자산이다.

갱신도 대화 한 줄로 한다(2026-06-17): `"방금 대화 바탕으로 이 스킬 업데이트해서 다음번엔 한 번에 처리하게 해줘"`. 대화 끝마다 학습 내용을 1~2문장으로 저장하면 시간이 갈수록 의도 파악이 정확해진다. (이 브레인의 self-evolving 규칙과 같은 원리.)

### 소상공인 플러그인 31스킬 (Cowork, 2026-06-01)

Anthropic이 클로드 데스크톱 앱의 **Cowork 탭 전용**으로 낸 소상공인 플러그인. 웹에선 안 되고 데스크톱 앱 설치가 필수다. 31개 스킬이 3대 영역으로 실무 도구와 직접 연결된다:

- 재무·운영: `/invoice-chase`(미수금 추적), `/plan-payroll`(현금흐름·급여 예측), `/tax-prep` — QuickBooks·PayPal·Stripe 연동.
- 영업·마케팅: 캠페인 러너, 리드 분류, 콘텐츠 전략가 — HubSpot·Canva·Mailchimp.
- 행정·관리: 계약 검토, 채용 공고 빌더, `/monday-brief` — Google Drive·DocuSign·Slack.

체감하기 쉬운 예: **`/job-post-builder`**(외부 연동 없이도 웹 검색으로 시장 데이터를 모아 채용 공고문 + 면접 가이드 + 오퍼 레터 3종 .docx 생성), **Contract Review**(계약서 업로드 → 레드 플래그·자동갱신 조항·누락 필수 조항을 시장 표준과 비교해 1차 리스크 검토). 31개를 다 도입할 필요 없이 시간을 가장 많이 잡아먹는 하나부터 맡기는 게 요령이다.

**안전장치**: 돈이 오가는 결제·고객 이메일 발송 등 중요 작업은 반드시 사용자 최종 승인 후 실행되는 **Human in the loop**로 둔다. 기본 지원 안 되는 앱은 **Zapier MCP**를 Cowork에 붙여 수천 개 앱으로 확장한다.

## 3. 직무를 통째로 맡기는 '직원'화 사례

여러 영상이 반복하는 세팅 골격은 동일하다: **① 스파링 파트너로 세팅**(설정의 'Instructions for Claude'에 비즈니스·역할 입력 + "내 가설의 취약점을 파고들고 잔인할 정도로 솔직하게 답하라"로 예스맨 탈출) → **② 커넥터로 실무 도구 연결** → **③ 통합 워크플로우로 묶기** → **④ 매일 쓰는 톱5 도구부터 연결**. 도구를 따로 쓰면 효과가 반감되고, 묶어야 앱 간 컨텍스트 스위칭 비용이 사라진다.

### 콘텐츠·고객센터 직원 (2026-06-25 / 2026-06-29)

커넥터가 클로드의 실질 위력이다: Gmail(긴급 메일 식별 + 내 스타일 답장 초안), Airtable(현황 요약·데이터 업데이트), Canva(카드뉴스·플라이어 제작), Blotato MCP(여러 SNS 한 번에 예약 발행). 통합 자동화 예시:

```
이메일 스캔 → 관심 주제 추출 → Canva 카드뉴스 제작
  → Blotato로 SNS 배포 → Airtable에 마케팅 로그 기록
```

공식 디렉토리에 없는 앱도 MCP 커스텀으로 연결할 수 있고, 막히면 클로드에 "이 앱 어떻게 연결해?"라고 직접 물으면 된다. (두 영상은 사실상 같은 4단계 골격을 콘텐츠/고객센터로 각각 프레이밍한 것. 원 출처는 Brendan Jowett.)

### 메타 광고 직원 (2026-07-02)

메타 광고 자동화 3단계. (1) **Opportunity Score** — 광고 관리자 첫 화면의 점수로, 메타가 대량 데이터로 도출한 개선 권고를 클릭 몇 번으로 적용. 100점 가깝게 유지하는 것만으로 기본 효율 확보. (2) **목적 중심 캠페인 설계** — 인지도/트래픽/참여/잠재고객/앱홍보/판매 6가지 목표를 사업에 맞게 정확히 고르고, 캠페인→광고 세트→광고 계층에서 지역·연령·관심사를 핀포인트해 예산 낭비 차단. (3) **Claude + MCP로 운영 자동화** — 메타가 AI 모델용 MCP 커넥터를 공식 지원. "오늘 광고 성과 어때? 보고서 뽑아줘" 한 줄로 실시간 데이터를 종합하고, ROAS 낮은 세트의 카피·타겟 개선안을 받아 즉시 실행한다. (원 출처 Ishan Sharma.)

### AI 웹 에이전시 (Fable 5 + Higgsfield, 2026-06-11)

Anthropic이 6월 9일 낸 Mythos-class 첫 공개 모델 **Claude Fable 5**는 비전 능력이 크게 향상돼(100만 토큰 컨텍스트, 비전+코딩 동시 SOTA) 스크린샷·링크 하나로 웹 레이아웃을 코드로 클로닝하는 데 최적화됐다. 여기에 **Higgsfield MCP**(Seedance 2.0 시네마틱 영상, Nano Banana Pro 이미지, Kling AI 모션)를 데스크톱 앱 Connectors에 연결하면 채팅창 하나에서 이미지·영상 자산까지 생성한다. 별도 **시네마틱 스크롤 스킬**(생성 영상을 프레임 단위로 슬라이싱해 스크롤 시 공간 이동 효과)을 주입하면 명령 한 줄로 3D 멀티섹션 사이트가 나온다. 영상은 이를 "24시간 웹 제작 에이전시" 수익 모델로 제안하지만, 판매가·마진 수치는 미검증 홍보성 주장이다.

### 활용 성숙도 5단계 (Peter Yang 사례, 2026-06-17)

직원 0명으로 14만 구독 뉴스레터를 운영하는 Peter Yang(전 Reddit·Meta·Roblox 제품 설계자)의 로드맵. **① 일상 질문 → ② 프로젝트로 복붙 줄이기 → ③ 프로토타이핑 → ④ 개인용 앱 구축 → ⑤ 개인 에이전트(전 프로세스 자동화).** 5단계 진입의 첫 관문은 브라우저 챗봇을 버리고 **컴퓨터 자원에 직접 접근하는 클로드 코드/Codex로 전환**하는 것. 그의 시스템 정점은 **개인 전략 고문(Personal Advisor)** 스킬 — 비즈니스 목표·핵심 원칙·에너지 관리(에너지 주는 일/뺏는 일) 한 페이지를 상시 참조해, 새 제안에 논리적으로 No 하도록 돕는다. 워크플로우는 산책 중 Super Whisper 브레인 덤프 → 클로드 코드 인제스트 → 뉴스레터·X·LinkedIn 다채널 자동 변환 → 주간 성과 브리핑이다.

## 관통 원칙

- **챗봇이 아니라 OS** — AI를 대화 상대가 아니라 비즈니스 명령을 수행하는 운영체제로 세팅한다. 회계사·변호사를 대체하는 게 아니라 그 사이의 단순 반복 업무(busy work)를 제거해 사람이 수익성 있는 일에 집중하게 한다.
- **누적 피드백이 해자** — 도구·스킬은 누구나 복제하지만 `learnings.md`에 쌓인 교정·원칙은 복제 불가능한 제도적 기억이다.
- **소비 모드 → 빌드 모드** — 뉴스 소비를 멈추고 하루를 통째로 비워 지난 업무를 브레인 덤프한 뒤 시스템을 세팅하라. 직원은 떠나지만 AI는 한 번 만들면 남고 매달 더 똑똑한 모델로 업데이트된다.
- **안전은 Human in the loop로** — 돈·외부 발송 등 되돌리기 어려운 작업은 항상 최종 승인 뒤 실행한다.
