# LLM 위키 실전 구축 (5대 빌딩블록 + 드림 시퀀스)

> Sources: AIMAX_PD (YouTube "클로드로 제2의 뇌 만들기"), 2026-06-09
> Raw: [2026-06-09-claude-second-brain-llm-wiki](../../raw/knowledge-management/2026-06-09-claude-second-brain-llm-wiki.md)

## Overview

[LLM Wiki](llm-wiki.md) 개념을 **클로드 코드 안에서 프롬프트 하나로 구축·운영하는 실전 레시피**를 정리한 영상이다. 벡터 DB·RAG·옵시디언 없이, 마크다운 폴더 구조와 운영 매뉴얼 파일만으로 "자가 진화형" 지식 시스템을 만든다는 것이 핵심 주장이다. AI 채팅의 치명적 한계 — **대화창을 닫는 순간 통찰이 휘발된다** — 를, 대화를 위키로 자동 정리해 **복리 자산**으로 바꾸는 것으로 해결한다. **이 저장소(두 번째 브레인)가 바로 이 레시피의 한 구현체**이며, 아래 "이 브레인과의 대조"에서 차이와 개선 여지를 짚는다.

## 5대 빌딩블록

영상은 시스템을 다섯 구성요소로 나눈다:

| 블록 | 역할 |
|---|---|
| **Inputs (Raw 폴더)** | 연구자료·웹기사·파일 덤핑장. 정리 안 돼도 OK — 조직화는 AI 담당 |
| **Wiki (조직화 레이어)** | AI가 Raw를 요약·연결해 검색 가능하게 재구성. `Index.md`(지식 지도) + `Log.md`(변경 기록) |
| **Outputs** | 위키 기반 최종 산출물 — PDF·슬라이드·앱 코드 등 |
| **claw.md (운영 매뉴얼)** | 시스템의 '운영체제'. AI가 읽기·쓰기·유지관리하는 모든 규칙. **AI가 스스로 이 파일을 갱신하며 진화** |
| **Dream Sequence (자가 진단)** | 주기 실행으로 모순 발견·중복 제거·최신화하는 '건강 검진' 루틴 |

## 운영 흐름

- **초기 설정**: 클로드 코드에서 프롬프트 실행 → 폴더 구조 + `claw.md` 자동 생성.
- **데이터 주입**: 웹 링크 공유하거나 Raw 폴더에 파일 투입만. **모바일에선 공유 → "저장해줘" 한 줄** → 클로드가 자동 Ingest + 위키 갱신.
- **지능형 인덱싱**: 주입 데이터를 분석해 `Index.md`에 핵심 개념·주요 엔티티·출처를 자동 정리. **`Processed.md`로 어떤 파일이 통합됐는지 추적**해 중복 작업 방지.

## 드림 시퀀스 (자가 유지보수)

영상이 "다른 지식관리 도구와 다른 결정적 이유"로 꼽는 요소. 카파시가 시스템의 **'건강 검진'**이라 정의했다고 소개한다.

- 매주/매일 지정 시간에 **자동 실행** → Raw의 새 파일 확인 → 기존 위키와 통합 → 모순·낡은 정보 감시 → 새 연결고리 자동 생성.
- 수동 실행도 가능: **"드림 시퀀스 실행해줘"** → 즉시 전체 최신화.
- 결과적으로 지식 베이스가 단순 저장소가 아니라 **스스로 학습하는 유기체**처럼 작동.

## 커스터마이징

- **운영 방식 전환**: "새 파일 주입 시 자동 업데이트하지 말고 드림 시퀀스에서 한 번에 처리해줘" 같은 지시로 즉시 변경.
- **주기 변경**: 주간 → 일간으로 최신성 강화.
- **딥 리서치 통합**: 특정 주제(예: AI 에이전트 산업 분석)를 딥 리서치시켜 결과를 즉시 위키에 통합 → 전문 지식 자산을 빠르게 축적.

## 이 브레인과의 대조 (구현 점검)

이 저장소는 위 레시피와 대부분 일치하지만 일부는 이름이 다르고 일부는 아직 없다:

| 영상의 요소 | 이 브레인의 대응물 | 상태 |
|---|---|---|
| Raw 폴더 | `raw/` (주제별 하위폴더, 불변) | ✅ 있음 |
| Wiki + Index.md + Log.md | `wiki/` + `wiki/index.md` + `wiki/log.md` | ✅ 있음 |
| claw.md (운영 매뉴얼) | `SKILL.md` + `CLAUDE.md` | ✅ 있음 (역할 분리) |
| Dream Sequence (자가 진단) | Lint 작업 (SKILL.md 작업 3) | ⚠️ 있으나 **수동 트리거·스케줄 없음** |
| Processed.md (통합 추적) | 없음 (`log.md`가 일부 대체) | ❌ 없음 |
| Outputs 폴더 | 없음 | ❌ 없음 |

→ **개선 여지**: ① Lint를 "드림 시퀀스"처럼 주기 실행(예: [/schedule], [/loop])으로 돌리면 자가 최신화가 자동화된다. ② 슬라이드·리포트 같은 산출물을 축적할 `outputs/` 도입을 검토할 만하다. 단, 영상은 홍보성이라("프롬프트 한 줄로 끝", "100일째 훨씬 강력") 과장은 걸러 읽는다 — 실제로는 이 저장소처럼 스키마·연쇄갱신 규칙이 뒷받침돼야 품질이 유지된다.
