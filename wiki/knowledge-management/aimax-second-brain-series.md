# AIMAX 세컨드브레인 제작 시리즈

## Overview

AIMAX_PD가 올린 세컨드브레인(제2의 뇌) 제작 3부작을 종합한 글이다. 세 편은 각각
**(1) 옵시디언+클로드 코드로 LLM 위키를 세우는 기초 워크플로**, **(2) 완성된 위키를
실제로 부리는 5개 운영 명령어**, **(3) 옵시디언 자체를 사고 도구로 쓰는 원칙**을 다룬다.

LLM 위키의 기본 개념(Raw→Wiki 컴파일, claw.md 운영 매뉴얼, 드림 시퀀스, ingest 3단계)은
이미 → [LLM 위키 실전 구축](llm-wiki-build-guide.md)과 [LLM Wiki](llm-wiki.md)에서 다뤘으므로,
이 글은 **3편이 추가로 더하는 구체 팁** — 노드 분할 기준, 핫 캐시, 5개 운영 명령어,
옵시디언 ACE 프레임워크 — 에 집중한다.

## 1편: 기초 세팅에서 추가되는 실전 팁

기본 3단계(ingest → 자동 조직화 → 지능형 쿼리)와 폴더 구조, 카파시 프롬프트 주입은
→ [LLM 위키 실전 구축](llm-wiki-build-guide.md)과 겹친다. 이 영상이 더하는 부분만 정리한다.

- **도구 조합**: 옵시디언(마크다운 시각화·백링크, 무료) + 클로드 코드(실제 파일 시스템 제어 엔진).
  옵시디언에 새 Vault를 만들고 그 안에 `Raw` / `Wiki` / `claw.md`를 둔다.
- **웹 자료 수집**: '옵시디언 웹 클리퍼' 확장으로 웹 기사를 즉시 Raw 폴더에 담는다.
- **노드 분할 기준 (핵심 팁)**: ingest 시 긴 파일 하나로 두지 말고 **5~10개 이상 세부
  페이지로 쪼갠다.** 유튜브 스크립트 1개를 넣으면 다음 축으로 분리하도록 지시한다.
  - 도구별 (예: Perplexity, VS Code)
  - 기법별 (예: WAT 프레임워크)
  - 개념별 (예: Vibe Coding, MCP 서버)

  쪼갠 페이지는 백링크로 자동 연결되어, 나중에 특정 도구를 물으면 그 도구가 등장한
  모든 자료의 맥락이 한꺼번에 호출된다. (이 저장소의 [지식 그래프](../graph/graph.json)가
  같은 역할을 한다.)

### 핫 캐시(Hot Cache) — 이 시리즈만의 추가 개념

개인 비서로 키울 때 붙이는 확장으로, 앞선 두 실전 글에는 없던 요소다.

- 최근 대화·핵심 정보를 **약 500자로 상시 요약**해 별도로 보관한다.
- AI가 매번 전체 위키를 뒤지지 않고 이 요약만 읽어 현재 상황을 즉시 파악한다.
- 영상은 이 방식이 매 질의마다 원문을 검색하는 RAG 대비 **토큰 사용량을 크게 줄인다**고
  주장한다(영상 표현 "최대 95% 절감"은 검증되지 않은 홍보 수치이므로 방향성으로만 참고).

## 2편: 완성된 위키를 부리는 5개 운영 명령어

제목은 "2가지 기술"이지만 실제로는 위키를 조회·활용하는 **5개 명령 패턴**을 소개한다.
이것들은 이 저장소의 **Query 작업**을 더 풍부하게 쓰는 방법에 해당한다.

| 명령 | 하는 일 |
|---|---|
| **context load** | "내 삶과 업무 전체 맥락을 불러와" — 볼트의 수천 파일·백링크를 한 번에 로드해 AI가 현재 상태를 파악 |
| **trace** | 특정 주제에 대한 장기간(예: 13개월) 사고 변화를 추적. 회의→확신으로 바뀐 지점 식별 |
| **connect** | 서로 먼 두 영역(예: 영화 ↔ 스타트업)의 연결 고리를 찾아 새 아이디어·비즈니스 모델 발굴 |
| **challenge** | 현재 신념과 과거 기록 사이의 모순·편향을 지적 → 확증 편향 방지, 비판적 사고 강화 |
| **emerge / graduate** | emerge: 흩어진 메모에 숨은 패턴을 명명. graduate: 아이디어 태그를 실제 프로젝트/앱 코드로 격상 |

원칙: **AI는 조언만, 기록과 결정은 본인 손으로.** 모든 데이터는 로컬에 두고
기록의 순수성을 지키는 것이 시스템을 지킨다.

## 3편: 옵시디언을 '사고 도구'로 쓰는 원칙

3편은 클로드 코드보다 **옵시디언 자체의 사용법**에 초점을 둔다
(출처로 Nick Milo의 "Linking Your Thinking"을 인용). LLM 위키를 옵시디언 위에
얹을 때 참고할 원칙들이다.

- **1. 데이터 소유권**: 노트를 클라우드가 아닌 내 컴퓨터의 볼트에 마크다운으로 저장.
  옵시디언이 사라져도 메모장·VS Code로 열려 플랫폼 종속이 없다.
- **2. 링크와 그래프 뷰**: `[[ ]]` 문법으로 노트를 즉시 연결하고, 아직 없는 노트도
  미리 링크해 사고 흐름을 끊지 않는다. 그래프 뷰로 허브 아이디어를 시각화하고
  백링크로 과거 생각을 현재 맥락으로 호출한다.
- **3. ACE 프레임워크로 조직화**: 처음부터 복잡한 폴더를 만들지 말고 **"구조는 자격이
  있을 때 만든다"**는 원칙을 따른다.
  - **Atlas** — 영원한 지식 (독서·학습·철학)
  - **Calendar** — 시간 기반 기록 (데일리·회고·저널)
  - **Efforts** — 기한 있는 프로젝트 (업무·태스크·목표)

  특정 주제는 **MOC(Maps of Content)** 허브로 묶는다.
- **4. 생산성 설정**: 자동 링크 업데이트 켜기(노트명 바꿔도 안 깨짐), 첨부 전용 폴더
  지정, Cmd+O 퀵 스위처, Cmd+P 커맨드 팔레트, 플러그인 욕심 버리기.
- **5. AI 콘텐츠 분리**: AI가 생성한 내용과 본인 통찰 노트를 분리 관리한다. 경계가
  흐려지면 볼트가 정보 쓰레기통이 된다. (이 저장소가 `raw/`와 `wiki/`를 나누고
  출처를 명시하는 것과 같은 원칙.)

## 세 편을 관통하는 관점

- 대부분은 AI를 '대화 상대'로 쓰지만, 핵심은 AI를 **지식 자산 운용 시스템**으로 쓰는 것.
  일회성 대화는 지식이 휘발되고, 위키 구조는 지식이 **복리화**된다.
- 세 편 모두 결국 **원문 보존 · 자동 조직화 · 주기적 유지보수 · 인간의 최종 판단**이라는
  같은 축으로 수렴한다. 이 저장소의 Ingest / Query / Lint 워크플로가 그 구현이다.

> 참고: 시리즈 제목·문구("500만명이 베껴간", "토큰 95% 절감")는 홍보성 과장이 섞여 있어
> 수치는 방향성으로만 받아들인다. 실제 품질은 이 저장소처럼 스키마·연쇄갱신 규칙이
> 뒷받침돼야 유지된다(→ [실전 구축](llm-wiki-build-guide.md) "이 브레인과의 대조" 참고).
