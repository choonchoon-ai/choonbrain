━━━━━━━━━━━━━━
AI와 대화하다 가장 허무한 순간.

대화창을 닫는 순간
그동안 나눈 깊은 지식과 맥락이 전부 사라진다는 것.

일반 AI 채팅은 '휘발성 지식'.
시간이 지날수록 정보가 쌓이는 게 아니라 흩어집니다.

테슬라 전 AI 책임자 안드레 카파시(Andrej Karpathy)가
이 문제를 깬 시스템을 공개했습니다.

'LLM 위키' — AI가 나 대신 정보를 기억하고 연결하는 동료가 되는 구조.

▎왜 'LLM 위키'인가

안드레의 시스템은 지식을 은행 이자처럼 '복리'로 쌓이게 만듭니다.

복잡한 서버·DB 기술 X.
인간과 AI 모두 읽기 쉬운 '마크다운 파일' 폴더만 사용.

3단계 작동 원리:

① 데이터 인제스트(Ingest)
PDF·회의록·유튜브 스크립트 등 원시 데이터를 클로드 코드에 제공
→ AI가 스스로 분석·정리

② 자동 조직화
클로드가 내용을 비교 분석
→ 인덱스(Index) + 로그(Log) + 주제별 위키 페이지 자동 생성
→ 사용자가 관계 설정할 필요 X

③ 지능형 쿼리
구축된 위키 기반으로 질문
→ 단순 검색이 아닌 '시스템 전체 맥락'을 읽고 답변

▎1단계. 도구 + 폴더 구조

필요한 도구 2개:
- 옵시디언(Obsidian) - 마크다운 파일 시각적 연결, 무료
- 클로드 코드 - 실제 파일 시스템 제어 엔진

옵시디언에 새 'Vault(보관소)' 생성 후 폴더 구조:

📁 Raw
정리되지 않은 원시 데이터 보관소

📁 Wiki
클로드가 정리한 결과물 공간

📄 claw.md
프로젝트 목적·작동 방식 지침 파일
→ 클로드가 매번 이 파일을 먼저 읽음

▎2단계. 시스템 가동: 카파시 프롬프트 주입

VS Code 또는 터미널에서 클로드 코드 실행
→ 안드레 카파시가 공개한 프롬프트 전문 복사 입력
→ 시스템 기초 공사 완료

추가 지침 한 줄:
"당신은 이제 나의 LLM 위키 에이전트입니다. 이 아이디어를 나의 세컨드 브레인 가이드로 구현하고 단계별로 안내하십시오"

→ 인덱스·로그 파일 자동 생성
→ 데이터 수신 준비 완료

웹 자료 수집 팁
'옵시디언 웹 클리퍼' 확장프로그램
→ 웹 기사를 즉시 Raw 폴더로 수집

▎3단계. 데이터 흡수 + 자동 분류

Raw 폴더에 원시 자료 투입
→ 클로드에 "Ingest 해줘" 명령

여기서 핵심:
긴 파일 하나 X.
내용 분석해서 5~10개 이상 세부 페이지로 쪼개 저장.

유튜브 스크립트 1개 입력 시 분리되는 노드 예시:
- 도구별 (Perplexity, VS Code…)
- 기법별 (WAT 프레임워크)
- 개념별 (Vibe Coding, MCP 서버)

분리된 정보는 백링크(Backlink)로 자동 연결
→ 나중에 특정 도구 질문 시
→ 연관된 모든 영상의 맥락이 한꺼번에 호출됨

▎4단계. 유지보수: 린팅(Linting)

지식의 건강 상태를 유지하는 정기 점검.

안드레의 방식:
정기적으로 AI 헬스 체크 실행
→ 일관성 없는 데이터 수정
→ 웹 검색으로 부족한 정보 보충
→ 새로운 연결 고리 발견

이 작업으로 지식 그래프가 시간이 갈수록 더 정교해집니다.

▎5단계. 핫 캐시(Hot Cache) 확장

개인 비서 시스템으로 키울 때 필수 기능.

작동 방식:
최근 대화·핵심 정보를 약 500자로 상시 요약 보관
→ AI가 매번 전체 위키 뒤질 필요 없이
→ 현재 상황을 즉각 파악

경제적 효과
기존 RAG 검색 방식 대비
토큰 사용량 최대 95% 절감

━━━━━━━━━━━━━━

핵심 관점 전환

대부분이 AI를 '대화 상대'로 씁니다.
승자들은 AI를 '지식 자산 운용 시스템'으로 씁니다.

차이는 명확합니다.
- 일회성 대화 → 지식 휘발
- 위키 구조 → 지식 복리

흩어진 문서·메모·자료를 방치하지 마세요.
오늘 클로드 코드 열고 첫 Vault 만들면
5분 뒤부터 절대 잊지 않는 동료가 생깁니다.

지식이 많아질수록 AI는 더 똑똑해지고,
당신의 비즈니스는 더 강한 데이터 기반을 갖게 됩니다.
